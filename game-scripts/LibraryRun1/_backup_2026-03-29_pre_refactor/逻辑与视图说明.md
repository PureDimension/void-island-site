# LibraryRun1 逻辑与视图说明

这份文档用于用中文概括当前 `logic.js` 与 `view.jsx` 的实现方式。  
以后只要我继续修改这两个文件，就同步更新这份说明。  
补充约定：从现在起，如果没有额外指令，不主动修改前端展示用的单位规则描述文字。

## 一、整体关卡流程

当前游戏不是“单关 + 一段剧情”，而是一条固定流程：

1. 教程关前剧情
2. 教程关战斗
3. 教程关后剧情
4. 第一关前剧情
5. 第一关战斗

后端通过 `FLOW` 数组描述这条顺序链。  
每一项要么是 `story`，要么是 `battle`。  
`moveToFlow()` 会负责把总状态切到对应剧情页或战斗页。

## 二、后端 `logic.js` 的结构

### 1. 顶层状态

- `phase`
  当前总阶段，可能是 `STORY`、`BATTLE`、`DEFEAT`、`VICTORY`。
- `flowIndex`
  当前走到流程链的第几项。
- `story`
  剧情页状态，包含当前页索引和页内容。
- `battle`
  当前战斗状态。
- `campaign`
  记录整局进度，例如影子的显现是否已经使用、哪些关已经通关、评级结果等。
- `history`
  历史快照，用于 `undo`。
- `rulebook`
  已学会规则的列表，前端 `RULES` 直接读这里。
- `pendingDefeat`
  失败暂挂态。失败时不会立刻结束，而是允许玩家回退或放弃。
- `finalResults`
  真正结算后的结果。

### 2. 剧情状态

剧情页由 `STORY_SCENES` 提供内容。  
每一页是一个对象，内部有 `paragraphs` 数组。  
前端读取当前页后，点击一次显示一段，全部显示完以后再翻到下一页。

### 3. 战斗状态

`battle` 中的重要字段有：

- `stageId`
  当前战斗属于教程关还是第一关。
- `playerUnits` / `enemyUnits`
  己方与敌方单位列表。
- `enemyLogicText`
  右侧展示给玩家看的敌方伪代码。
- `actionLog`
  完整日志。
- `destroyedUnitIds`
  本关已经被摧毁的单位列表。
- `pendingTurnEffects.overloadPower`
  影子本回合准备显现到的 POWER。
- `lastPlayerAttackerId`
  最近一次主动攻击过的玩家方单位。
- `lastEnemyAttackerId`
  最近一次敌方自动出手的攻击者。
- `guide`
  当前关卡的教学步骤状态。

## 三、教程接口与规则手册

### 1. 教学步骤

教程与第一关开场提示都来自 `GUIDE_SETS`。

每一步都可以定义：

- `speaker`
  谁在说话。当前都是水铃儿。
- `text`
  显示给玩家的提示文本。
- `mode`
  这一步如何推进。
- `highlights`
  要高亮哪些区域或单位。
- `callouts`
  额外展示在教学卡片里的高亮说明文字。
- `addRules`
  这一步要加入 `rulebook` 的规则。

### 2. 当前支持的教学模式

- `manual`
  玩家点击“继续”后进入下一步。
- `attack`
  必须按要求完成一次指定攻击。
- `confirm`
  必须确认一次敌方回合。
- `undo`
  必须通过右上角 `BACK` 执行一次教程指定的回退。
- `free`
  表示引导结束，允许自由行动。

### 3. 规则手册

`RULE_TEXT` 里维护所有会被教学步骤解锁的规则。  
`learnRules()` 与 `syncCurrentGuideRules()` 会把新规则加入 `state.rulebook`。  
前端右上角的 `RULES` 会把这些内容弹出来。

第一关开场提示目前分成三段：

- 先提示“BUFF 也是一种能力”，这一条会写进 `RULES`
- 再提示密文需要特殊处理，这一条只是关卡提示，不写进 `RULES`
- 最后提示伪装模块的特殊站位与操控方式，这一条也只是关卡提示，不写进 `RULES`

## 四、第一关敌方逻辑

### 1. 展示给玩家的伪代码

第一关右侧现在显示的是敌方视角版本：

```text
if 上一个主动攻击的敌方单位存活：
  在己方中选择 POWER 高于它且最低的一个单位
  if 找到单位：
    该单位攻击该敌方单位
  else：
    本轮不攻击
else：
  本轮不攻击
```

这里的“敌方/己方”是站在关卡内敌人自己的视角说的。

### 2. 实际判定

虽然伪代码用的是敌方视角，但后端内部仍然是按玩家视角计算：

1. 读取 `lastPlayerAttackerId`
   也就是上一个主动攻击过的玩家方单位。
2. 如果这个单位仍然存活，就把它当成敌方要回击的目标。
3. 在“可视为敌方攻击者”的单位中，选择 `POWER` 高于它且最低的一个。
4. 若找到攻击者，则该单位向这个玩家方目标发动攻击。

这里“可视为敌方攻击者”的对象包括：

- 正常敌方单位
- 伪装模块

## 五、单位能力的 hook 化

### 1. 设计目的

所有单位能力都尽量挂到 hook 上，而不是写死在一段大 `if` 里。  
这样第二关、第三关新增单位时，只需要补新的 hook，不需要推翻整套战斗结算。

### 2. 当前 hook 时点

- `modifyCombatPower`
  战斗中，修改本次战斗的计算 POWER。
- `preventCombatDestruction`
  本次战斗会被摧毁时，是否阻止摧毁。
- `afterCombat`
  一次战斗完全结算后触发。
- `onDestroyed`
  单位被摧毁时触发。
- `previewCombatBonus`
  给前端提供稳定的 `+x` 预览。

### 3. 当前单位能力对应关系

- 影子  
  `modifyCombatPower` 接收 `overloadPower`，把本回合战斗 POWER 直接改成显现值。
- 战斗模块  
  `preventCombatDestruction` 免于因战斗被摧毁；`afterCombat` 战后 `POWER -1`。
- 电磁干扰模块  
  `onDestroyed` 在战斗中被摧毁时，把【EMP】施加给对手。
- 成长模块  
  `modifyCombatPower` 与 `previewCombatBonus` 都读取“本关已摧毁单位数”。
- α  
  主动攻击时本次战斗 `+3`。
- β  
  被攻击时本次战斗 `+3`。
- γ  
  只要 α 或 β 参战，自己永久 `-1`；若它们在该战斗中被摧毁，再额外 `-1`。
- 伪装模块  
  当前没有单独 hook，它的特殊性主要通过目标判定和前端双半区交互体现。

## 六、战斗结算流程

### 1. 玩家攻击

当玩家执行 `attack`：

1. 校验当前确实处于 `PLAYER_TURN`
2. 校验攻击者是否是可指挥的己方单位
3. 校验目标是否是允许玩家攻击的敌方对象
4. 如有教学限制，则先通过教学检查
5. 进入 `settleCombatOutcome()`
6. 战斗后检查胜负
7. 若未结束，再执行一次敌方自动出手

### 2. 单次战斗

`settleCombatOutcome()` 的顺序是：

1. 记录前一次战斗的攻击者与防守者
2. 用 hook 计算双方战斗 POWER
3. 比较胜负
4. 若单位带有“免于因战斗被摧毁”的能力，则取消摧毁
5. 真正执行摧毁
6. 执行 `afterCombat` hook
7. 全场统一检查越界规则：`POWER < 0` 或 `POWER > 9` 会立刻被摧毁

### 3. EMP 的处理

【EMP】的效果是：

- 获得时立刻 `POWER -3`
- 若带着【EMP】的单位被摧毁，则把【EMP】传给最后一次与之战斗的单位

单位的 `buffs` 目前只实现了这一种异常状态。

## 七、前端 `view.jsx` 的结构

### 1. 剧情页

- 文本位于偏上的整块空间里，不使用中心小卡片
- 点击一次出现一段
- 当前页所有段落都出现以后，再点击进入下一页
- 右下角有小号提示文案

### 2. 战斗页布局

战斗页分为两列：

- 左侧主战场  
  上方敌方单位，中间箭头与简略信息，下方己方单位。
- 右侧信息面板  
  包含敌方伪代码、当前选中单位详情、BUFF、影子的显现按钮和 `ATTACK / CONFIRM`。

### 3. 高度自适应

前端没有再单纯写死 `vh`。  
`useBattleViewport()` 会读取当前游戏视图距离浏览器顶部的真实位置，再计算“从这里到底部还剩多少高度”，并把结果写成 CSS 变量 `--library-run-available-height`。  
战斗主区域直接使用这个值，所以能更贴近房间页的真实剩余空间。

### 4. 音乐播放器屏蔽

因为播放器在 `app/layout.jsx` 里全局挂载，前端不能直接删掉它，所以这里用了两层保险：

1. 进入游戏时给 `body` 加 `library-run-hide-player`
2. `useHideMusicPlayer()` 会主动查找 `.fixed.bottom-4.left-4.z-50` 中带 `audio` 的节点，并直接把它隐藏
3. 同时保留 CSS 兜底

这样即使布局重新渲染，播放器也会继续被隐藏。

### 5. 教学高亮

前端会读取 `battle.currentGuideStep`。

`highlights` 现在支持：

- 单位高亮
- 敌方行 / 己方行高亮
- 中央信息高亮
- 右侧伪代码区高亮
- 右上角 `BACK / RULES / LOG` 高亮
- 右侧 `BUFF / 描述 / 标签 / ATTACK` 高亮

这套接口后面可以直接复用到第二关、第三关的开场提示。
现在高亮不只是淡淡一层底色，而是会附带更明显的描边与发光，方便玩家一眼看出当前教学重点。
另外，教学卡片现在也支持额外的高亮文字条目，用来明确展示“上一个攻击者是谁”“本次战斗的 1+3 从哪里来”这种解释性信息。

### 6. 单位交互

- 可选攻击者显示浅蓝
- 已选攻击者显示亮蓝
- 可选目标显示浅橙
- 已选目标显示亮橙
- 敌方自动出手时，攻击者保持敌方橙色，被攻击的己方保持己方蓝色，不会把己方也染成橙色
- 伪装模块拆成上下两半  
  上半段走敌方目标逻辑，下半段走己方攻击者逻辑
- 被选中的攻击者或目标右侧会出现一个小 `×`，用于取消选择

### 7. 箭头与日志

- 选择攻击者与目标后，中间会出现一条蓝色箭头
- 敌方自动出手时，会出现橙色箭头
- 屏幕中间只保留简略信息
- 右上角 `LOG` 才显示完整日志
- 敌方自动出手后，后端其实已经完成了结算；但在玩家按下 `CONFIRM` 之前，前端会用一个临时显示态把这次敌方攻击造成的“死亡标记”先隐藏，等确认后再真正显示单位已被摧毁
- 为了让伪代码缩进正常显示，右侧伪代码文本额外启用了保留空格与换行的样式

### 8. 教程卡片与回退修正

- 教程卡片现在放在战场正中间，而不是压在己方单位上方
- 但如果某一步需要强调战场正中的简略结果，教学卡片也可以临时移到侧边
- 卡片外框和战场高亮都做了更明显的描边与发光
- 当前端已经进入“敌方攻击等待确认”状态时，如果玩家直接点 `BACK` 回退，前端会主动清掉本地残留的 `enemyConfirm / arrow / target` 状态，避免回退后还保留上一轮未确认的敌方攻击表现
- 教程里的 `BACK` 还额外支持“引导式回退”：它会把局面恢复到教程预设的检查点，然后继续后续教学，而不是单纯只退本地一步

### 9. 单位能力说明的动态补充

对于依赖“上一个攻击者”或“上一个被攻击者”的单位，前端不会改写它们原本的描述文本，而是在右侧描述下方额外补一行动态说明，例如：

- 上一个攻击者是谁
- 上一个被攻击者是谁

这样既保留原始规则描述，又能让教程里提到的上下文直接在面板里看见。

另外，确认敌方回合之前，右侧说明面板读取的是“临时显示态”的战场数据，而不是已经确认过的最终显示态。这样像信号工蜂、监控工蜂这种依赖上一战上下文的说明，就不会在 `CONFIRM` 前提前跳到下一次战斗后的结果。
